---
title: Credits
description: Gate spending and debit registered-user balances from durable usage evidence
---

Use Credits to give registered users a starting balance, check it before paid work, and display the remaining amount in the sidebar. Core continues to record and reconcile usage with or without this plugin.

## Installation

```bash
bunx @chat-js/cli@latest add credits
bun db:generate
bun db:migrate
```

The CLI registers the `credits` router, billing policy, account summary, and `UserCredit` schema. Review generated SQL before applying it. The reference app already includes Credits; extracting it preserves the existing table and data without a new migration.

## Usage

New balance rows start at **50 cents ($0.50)**. Reading the balance or checking spending availability creates a missing row. A positive usage debit also creates it if needed.

Admission requires a strictly positive balance. This check does not reserve money or estimate a turn's final cost: concurrent and in-flight work can leave a negative balance. The next admission then fails.

Core sums provider costs using database decimal arithmetic, rounds up once per turn to whole cents, and subtracts only the unpaid difference. Receipt writes, the debit, and the settlement marker commit in one transaction. Replayed evidence does not charge twice. Unknown costs remain pending until reconciliation resolves them.

Guest message allowances remain core behavior and do not create or debit a credit balance. This plugin does not add payments, subscriptions, top-ups, or an administrative balance editor.

## Storage

| Table | Fields | Purpose |
| --- | --- | --- |
| `UserCredit` | `userId`, `credits` | Integer balance in cents, deleted with its user |

Core retains `EveUsage`, its `chargedCents` settlement marker, receipt deduplication, and durable reconciliation cursors. The plugin owns balance storage and policy.

## Customization

- Edit `plugins/credits/credits-schema.ts` to change the default for new balance rows, then generate and apply a migration. Existing balances stay unchanged.
- Edit `credits-queries.ts` for balance reads and admission policy.
- Edit `billing.ts` for debit behavior. Use the supplied database transaction; throwing rolls back the receipt and debit together. Keep external payment calls out of this operation.
- Edit `balance.tsx` and `use-credits.ts` for the sidebar display and balance refresh.

Only one installed plugin can provide billing. Its `billing.ts` entry must load in both native EVE and Next.js, without importing web routers or request helpers. See the [Plugin API](../reference/plugin-api).

## Without Credits

A new app without this plugin has no `UserCredit` table, credits router, or balance display. Spending passes the optional monetary gate, while authentication, guest quotas, and usage reconciliation still apply.

Adding Credits does not run a historical backfill. However, a later receipt for a previously unbilled turn computes its unpaid total from all recorded evidence for that turn. Decide how to settle existing in-flight turns before enabling billing on an app that previously ran without it. See [Credit Tracking](../cookbook/credit-tracking) for the accounting flow.
